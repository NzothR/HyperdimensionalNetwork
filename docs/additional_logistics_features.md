# 超维网络：额外物流功能提案

> 文档状态：**待用户评审；当前只记录设计，不代表已批准实现。**
> 更新日期：2026-10-20
> 范围：阅读书籍、垃圾桶/自动垃圾桶、自动存入网络。

本文把已提出的功能目标与仍需确认的交互规则分开记录。进入实现前，以用户评审后的版本为准。当前不改变旧 `DestroyStorage`；自动阅读书籍会在实现阶段检查 `D:\SteamLibrary\steamapps\common\7 Days To Die\mod修复\自动阅读书籍(F7开关)` 的代码和游戏接入方式，再按超维网络的库存事务重接。

## 1. 共同原则

- 背包和快捷栏属于具体玩家；共享网络库存属于当前 `NetworkId`。每次操作由服务端确认玩家身份、来源、数量和当前网络。
- 对原版操作（尤其是阅读书籍）复用原版效果和资格判断，不在模组侧伪造阅读效果、技能等级或物品堆叠身份。
- 自动处理按实际库存变化触发，避免逐帧轮询。模组自身搬运物品、退款和归还暂存物品时要带操作来源，避免重复触发自动规则。
- 每次处理按精确物品变体和实际成功数量提交；失败时保留或归还尚未处理的物品。关键阶段日志受 `DebugLog` 统一控制。
- 同一物品可能同时匹配多种自动行为。规则需要有稳定顺序和单一处理结果，避免同一堆物品被重复转移或销毁。

## 2. 阅读书籍

### 2.1 背包自动阅读

- 监测当前玩家背包中新增或堆叠数量增加的可读书籍，并在满足原版阅读条件时自动阅读。
- 处理范围限于玩家自己的背包，不搜索网络库存，也不处理其他成员背包。
- 使用当前玩家的原版阅读/使用流程，使效果和资格判定与手动阅读一致。每次只消耗原版实际成功阅读的书籍数量。
- 对有等级上限的制作杂志，只读到该玩家相应制作等级满级；已读完、已满级或当前不可阅读的书籍不消耗。
- 建议仅对运行期间实际进入背包的数量变化触发，不因登录、重连或首次打开背包自动扫描已有库存。玩家可通过开关启用或停用自动阅读。

### 2.2 网络批量阅读按钮

- 在超维网络界面增加“阅读书籍”按钮。玩家点击后，服务端以点击者为唯一效果接收者，扫描其当前网络中该玩家尚未阅读或对应制作等级尚未满级的书籍。
- 阅读资格按发起玩家的状态判断；共享网络里其他成员的阅读进度不改变本次筛选。
- 同一网络同一时间只允许一个批量阅读事务。操作开始时计算本次需要的书籍数量，将这些数量从公共可用库存转入订单式运行期隐藏空间，避免其他成员同时取走或重复预留。
- 服务端逐本调用原版阅读流程。只有确认效果成功应用才消耗相应书籍；完成后把未使用的数量退回原网络。归还物品属于原事务回收，不再次触发自动存入或自动出售规则。
- 若玩家离线、换网、世界关闭或流程失败，停止后续阅读，并把尚未使用的书归还绑定的原 `NetworkId`；已经成功应用的阅读效果不撤销。
- 事务只占用计划阅读的物品数量。其他网络物品可继续正常存取；被占用的书籍数量不可被其他消费请求使用。

### 2.3 待评审的阅读细节

- 自动阅读开关及设置是否按玩家保存；提案默认按玩家保存。
- 批量阅读是否显示逐本进度、提供取消按钮，以及每个游戏循环最多处理多少本。提案倾向异步分批执行，避免一次处理大量书籍造成卡顿。
- 点击时如果某种书籍的可读数量超过当前所需数量，按资格计算出最小数量，只暂存这些书；剩余书籍留在公共库存。
- 如果游戏原版没有可靠的“效果已成功应用”确认点，则该书暂不自动处理并记录诊断，不以扣书后猜测成功。

## 3. 垃圾桶

### 3.1 手动垃圾桶

- 增加垃圾桶按钮，打开仅供当前玩家使用的临时容器界面。玩家可以把物品放入其中；明确关闭容器时，销毁其中已接收的物品。
- 临时容器不属于网络库存，不落地、不持久化，也不对其他成员可见。物品放入后须先确认来源背包已实际扣除，再进入临时空间；只销毁容器实际接收的数量。
- 关闭时清空临时空间并记录总物品种类数和数量，不逐件刷日志。

### 3.2 自动垃圾桶

- 提供规则列表及启停控制，持续监测规则所选来源中的新增物品，并按规则顺序销毁匹配数量。
- 可选来源至少包括：当前玩家自己的背包、当前玩家自己的快捷栏、当前所属网络公共库存。不会扫描其他玩家的背包。
- 规则可匹配物品类型/变体，并可包含允许列表、排除列表和数量上限；具体筛选条件可复用商人规则选择器已有能力，避免建立第二套分类定义。
- 背包/快捷栏规则只作用于配置该规则的玩家。涉及共享网络库存的规则属于网络行为，提案建议由网络管理员编辑并由服务端执行；是否允许普通成员编辑有待确认。
- 每次删除都在服务端检查当前所有者、物品数量和规则版本；其他网络操作不能同时消费同一数量。仅删除成功提交的数量。
- 新建或启用规则后，先按规则顺序扫描所选范围内的现有库存一次，再持续监测后续库存变化。规则编辑或开关切换不能造成重复销毁。

## 4. 自动存入网络

- 增加个人自动存入规则，持续监测当前玩家自己的背包和快捷栏。匹配的物品自动从原格子转入该玩家当前所属网络。
- 只处理已真实进入背包/快捷栏的物品数量增加；不会搜索周边容器、其他玩家背包或网络库存，也不会在网络取出物品时立即将其存回。
- 建议个人配置与规则跟随 `PlayerId`，成员换网后规则保留并作用于新网络；每次存入仍重新验证当前网络身份和服务端权限。
- 默认转移匹配堆叠中可转移的全部数量；网络拒收、容量/事务失败或物品已被其他操作改变时，物品留在原位置或按实际完成量部分提交，不报告未完成数量为成功。
- 可沿用商人规则中的物品选择、分类、品质和排除条件 UI；不复用商人价格、预算、计划时间等与入库无关的字段。
- 自动存入经过统一公共入库管线，因此现有网络自动出售规则可继续检查实际入库物品。自动存入自身产生的玩家库存变化不重复触发自身监听。

## 5. 多规则协调与多人语义

以下是实现提案，需要在开发前确认：

1. 规则列表按从上到下评估；同一物品数量只由首个匹配且启用的动作处理，不能同时自动存入并自动销毁。
2. 手动存取、制作和交易等玩家主动操作优先完成；自动规则只处理事务成功后仍留在来源中的数量。
3. 各项规则由稳定的规则 ID 和版本标识。一次扫描期间若规则发生修改，当前事务按开始时的规则快照完成或安全取消，不混用新旧条件。
4. 玩家库存操作与网络库存事务需要分别串行化；共享网络中的批量阅读、自动销毁和自动存入不能越过同一物品数量的预留/扣减协调。
5. 自动销毁共享网络物品的权限需明确。提案默认把网络内物品的自动销毁规则作为网络级配置，仅管理员可编辑；个人自动存入和个人背包/快捷栏清理规则跟随玩家。

## 6. 建议实施顺序

1. 自动存入网络：先复用库存变更监听、规则匹配和统一入库事务。
2. 手动垃圾桶及自动垃圾桶：手动入口先确定临时容器的生命周期；自动规则复用已建立的物品规则模型，并增加明确的销毁确认提示。
3. 阅读书籍：检查旧自动阅读书籍 mod 和当前游戏版本的原版阅读入口，再实现背包自动阅读与网络批量阅读事务。

这是建议顺序，不是已确认排期。三项功能均待本设计稿评审后再拆分实现。

## 7. 开发前需确认

- 自动阅读书籍是否只处理运行中新增到背包的物品，还是启用开关时也扫描已有背包书籍。
- 自动垃圾桶是否允许网络管理员规则影响整个共享网络；规则修改权限是否仅限管理员。
- 手动垃圾桶遇到断线、退出世界或异常关闭时，临时空间中的物品应销毁还是退回原来源。提案倾向异常中止时退回可回收物品，只有玩家明确关闭垃圾桶时才销毁。
- 自动垃圾桶与自动存入规则相互冲突时是否采用列表优先级；提案采用一条匹配物品数量只执行首个动作。
- 规则筛选是否需要精确品质/变体、堆叠最低保留量、每次处理数量上限，以及自动存入失败后的重试时机。
- 阅读按钮运行时的进度显示、取消时机及批量速率。
