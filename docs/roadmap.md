# 超维网络：分阶段实施与待定细节

本文记录已确认的阶段安排、已验收范围、已确认的后续功能规则和待讨论候选。功能行为讨论完成后再补齐对应设计；本文不把尚未确认的候选行为当作已定需求。

## 当前状态

用户已确认阶段 1、2、3 验收完成。下一步进入多人开发第一阶段。其间所有新增功能从设计时考虑多人使用，避免功能完成后再补一轮多人架构。交易功能规则现已确认并写入本文；自动读书、书籍处理和远程箱子链接均已从规划中移除；下一个讨论主题为自动化链式合成与补货。

多人开发第二阶段包含成员关系操作和最终多人验收。朋友参与的多人测试统一安排在其他功能完成后，减少反复占用朋友时间。

## 阶段 0：目标版本和接入契约

目标游戏版本、运行时/.NET/Mono 限制、Harmony/API 接口及首发模组兼容矩阵仍需在多人改造和新功能接入时持续核实。旧 `DestroyStorage` 只用于盘点功能与补丁入口，不作为新实现契约。

## 阶段 4：多人开发第一阶段——服务端基础、既有功能多人化和其他功能

### 网络与交易核心

- 每个网络具有持久、唯一、不会复用的 `NetworkId`；建议采用 GUID 或等价的全局唯一格式。所有库存操作明确指定网络 ID，不按显示名称或临时实体 ID 混用库存。
- 使用稳定玩家 ID 记录玩家当前所属网络。玩家首次进入存档时得到自己的独立网络，并作为该网络唯一管理员。
- 服务端拥有网络库存、成员关系和交易结果的最终权威。客户端请求查询/变更并显示服务端确认后的状态。
- 交易具备唯一 ID、网络修订号和可恢复的持久化语义，重复请求不能重复扣料或加料；多人同时消费时不能超额使用。
- 建立网络插件槽与功能解锁服务及插件管理界面。插件槽默认 10 个、槽位数由服务端配置决定；服务端保存并校验插件状态，只有网络管理员可以安装、移除或替换插件。成员与管理员都能使用已解锁的网络功能。
- 已验收阶段 1–3 的界面存取、制作、工作站、装备维修、建筑修复/升级、载具燃料/维修都接入服务端请求流程。操作要保留发起玩家上下文，区分共享材料与玩家个人收益/进度。
- 其他候选功能都在本阶段设计和开发；每项功能都明确操作者、共享库存影响、收益/进度归属及失败、取消、断线和重试语义。

### 服务器管理员控制台指令

服务器管理员权限与网络内“管理员/成员”角色是两种不同权限。以下维护指令只允许服务器管理员执行，并在服务端检查参数和权限：

1. 按源网络 ID 和目标网络 ID 迁移库存物品。此操作只搬库存，不改变网络成员关系或网络 ID；成功后源网络保留为空。
2. 按网络 ID 清空库存。网络 ID 和成员关系保留；建议要求显式确认参数。
3. 按玩家 ID 查询其当前网络 ID 和网络角色。共享网络中的玩家返回同一个网络 ID。
4. 列出当前存档中已知玩家的玩家 ID、显示名称、在线状态、当前网络 ID 和角色。
5. 按玩家 ID 设置网络管理员，不接收网络 ID 参数。服务端先查该玩家当前所属网络，将其设为管理员，并将同网络其他管理员降为成员；不影响其他网络。

库存迁移和玩家加入网络是不同操作：维护指令只迁移物品；成员加入会改变成员关系，并按第二阶段规则注销来源网络。

### 本阶段验收边界

开发期间构建并回归已验收的单机流程。最终的多人游玩验收延后到多人开发第二阶段，并等其他候选功能都完成后集中进行。

## 阶段 5：多人开发第二阶段——成员关系、UI/玩家指令与集中验收

### 邀请和成员规则

- 邀请即时发送，只能邀请当前在线玩家；不创建面向离线玩家的待处理邀请。
- 网络管理员和成员都能邀请别人；受邀玩家必须接受后才加入，加入者初始为成员。
- 一个玩家同一时刻只属于一个网络。成员要换网时先退出当前网络，再接受目标网络邀请。
- 成员可主动退出；网络管理员不能普通退出，也不能踢出自己。管理员可以踢出成员。
- 网络只有一个管理员。管理员可通过明确的“合并加入”操作加入别人网络，个人网络物品并入目标网络，原网络注销，玩家降为目标网络成员；个人网络还有其他成员时，先由他们离开或被移出。
- 成员退出或被踢后，立即失去原网络访问权并得到一个新的空网络，成为新网络管理员。此前的共享库存留在原网络，不按存入者返还。
- UI 和玩家指令共用服务端成员/权限服务。踢出、退出或加入完成后，旧界面和进行中的请求不能继续操作旧网络。

### 最终多人验收

朋友参与的多人验收等所有新增功能完成后集中进行，覆盖：

- 各玩家私人网络隔离；网络 ID 稳定且不同网络库存不串联。
- 管理员/成员邀请、接受、退出、踢出、网络管理员恢复和合并加入。
- 合并中断、服务器重启、重复请求和存档恢复不会重复加物品或丢物品。
- 多名玩家并发取出或消耗材料时，库存和修订保持一致。
- 阶段 1–3 及新增功能在多人下的发起者、受益玩家、库存扣除和失败回滚正确。
- 离线重连后成员关系与网络 ID 正确；已离线玩家不可接收新邀请。

多人测试的实际执行放在此阶段末尾，不要求朋友参与每个功能的开发迭代。

## 其他功能候选与待确定细节

以下内容来自现有架构规划及候选功能清单。它们计划放入多人开发第一阶段逐项讨论和实现；并非全部承诺实现。商人交易按本节已确认设计独立定义，不以旧模组作为功能参考。

### 弹药、换弹和弹药银行

**已确认的行为：**弹药银行作为网络插件，只有安装了弹药插件的网络才能把网络弹药提供给枪械换弹和弹药数量显示。弹种与当前选择由枪械原版数据决定；适配器按枪械请求的弹种处理，不另外实现弹匣或弹药变体兼容匹配。弹药会在换弹请求中通过统一资源事务预留/扣除，不按每发射击单独请求网络库存；已装入枪械的弹药仍由原版枪械弹匣机制消耗。背包/快捷栏实体弹药优先，网络库存作为后续来源。

**显示与缓存：**缓存保持轻量和增量更新。快捷栏变化时只检查变化槽位；切换武器不全量重建缓存。快捷栏中没有远程武器时不查询网络弹药；背包变化和共享网络修订变化时使相关数量缓存过期，HUD/弹药轮盘按当前显示武器刷新。弹种数量可批量查询，但不可逐帧或按每种弹药分别发远程请求。显示缓存不参与扣料授权。

**仍需实现时验证：**按整弹匣计量的武器、发射器、换弹取消/中断、弹种切换时已装弹药退回的原版行为，以及管理员移除弹药插件时在途换弹的处理。

### 网络插件系统

**已确认的基础规则：**网络功能可通过插件解锁，弹药银行由弹药插件解锁。每个网络有专用插件槽，默认 10 个，槽位数量由服务端配置决定。插件槽内容由网络管理员独占变更权限；成员可使用网络已解锁的功能，但不能安装、移除或替换插件。插件状态由服务端权威保存和检查。

插件槽内容变更与库存变化作为网络事务处理，服务端串行提交；管理员唯一写入权限减少多个成员同时改槽冲突，但不会替代服务端校验。具体插件效果、插件之间的依赖/冲突、槽位配置缩减后超出容量的处理，以及网络合并时插件槽物品/状态的迁移规则，在逐项功能设计时确定。

### 出售和商人交易

**插件与多人归属**

- 手动出售、聚合购买、自动出售和自动购买均由网络的“交易插件”解锁；未安装插件的网络不能使用这些功能。
- 自动出售/购买规则仅网络管理员可创建、修改和删除。管理员在线时自动交易可应用其当下有效的原版交易加成；管理员离线时不应用个人加成，使用基础价格/商人报价。手动交易使用实际发起玩家的有效加成。
- 服务器是网络库存、货币和自动规则执行的权威方。并发扣除网络货币、物品或交易库存时走统一服务端交易协调；自动操作不归属任意在线玩家。

**手动出售**

- 出售给不对应任何现实 NPC 的虚空商人。支持多人同时出售；所选物品和网络货币变化由统一原子交易处理。
- 售价默认进入共享网络；交易界面允许切换为进入打开该界面的玩家背包。交易按游戏的物品售价和虚空商人默认出售比例计算，并使用发起玩家的原版出售加成；不读取某个现实商人的库存或专属价格覆盖。
- 遵守原版可售条件。物品不可出售标记或基础/最终计算售价不大于 0 时，不能手动出售或被自动出售。品质、耐久状态、经济价值、出售比例、全局交易价格设置和适用的交易加成按游戏售价公式处理。

**自动出售**

- 管理员通过自动出售界面指定要出售的物品与品质规则。匹配方式只判断品质等级，不判断改装件：精确匹配指定品质；模糊匹配忽略品质；条件匹配使用品质比较符 `>`、`>=`、`=`、`<=`、`<`。品质条件不匹配没有品质等级的物品。
- 新增或更改/添加出售标记时，对网络库存做一次全量匹配扫描并出售现存匹配物品。移除规则不触发扫描。
- 新物品进入网络时只检查该物品及受影响规则；符合规则且可售时立即出售，收益进入网络。物品被同一笔存入/出售交易消费，避免存入后重复触发。
- 没有正售价或原版不可出售的物品跳过，不产生出售收益。

**手动聚合购买**

- 网络购买入口实时扫描网络成员可交易的现实商人，并把当前商品聚合到一个与原版购买相同操作习惯的界面。购买仍实际向对应商人交易并减少该商人的真实库存；聚合视图不是虚构商店。购买后商人库存与玩家前往该商人时一致。
- 商品记录始终保留来源商人和报价。同一物品、同一价格可以合并显示并汇总可买数量；同一物品不同价格分开展示。手动购买使用打开界面的玩家作为交易发起者，按该玩家的有效购买加成计算。
- 购买目标默认进入网络；发起者可切换为进入自己的背包，选择按玩家持久保存。背包满时沿用原版行为，将购得物品掉落到地上。
- **商人互斥锁：**聚合购买打开时，服务端扫描并锁定所有当前可用的商人来源，锁在界面关闭、取消、玩家离线或操作失败清理时释放。扫描跳过已被原版交易或其他聚合购买占用的商人；若仍有可用来源则展示这些来源，若没有可用来源则提示所有商人繁忙。
- 锁定按现实商人实体生效、跨网络共享。聚合购买占用期间，其他玩家从普通商人界面发起交易时由原版交易锁拒绝并显示原版拒绝提示。不同网络也共享同一商人锁状态。
- 原版 `LockManager` 单次锁请求最多支持 5 个目标。若可交易商人来源超过此限制，实现时使用服务端商人锁协调器，并让原版 `EntityTrader` 交易锁请求识别该协调器占用、按原版方式拒绝交互；不得逐个加锁形成未锁住全部来源的竞态窗口。

**自动购买**

- 管理员可配置自动购买规则，也可点“立即执行”一次运行全部规则。定时触发与手动执行都立即检查规则；手动执行不等下一个定点。
- 普通规则包含目标物品/品质匹配、当前网络库存数量及比较条件、单次最大购买数量、当前网络公爵币及比较条件、单次最高花费（默认无上限）和计划时间。库存数量条件与公爵币条件均为触发门槛，条件全部满足才执行；单次最高花费单独限制实际支出。
- 品质匹配只判断品质等级，不判断改装件：精确匹配指定品质、模糊匹配忽略品质、条件匹配使用 `>`、`>=`、`=`、`<=`、`<`；设置品质条件时无品质等级物品不匹配。
- 批量规则可购买所有商品、某个商品类别等一组商品，不设置单一商品的库存数量阈值/条件，只检查公爵币条件和品质购买条件。单次最高花费仍适用；预算不足时按报价由低到高购买，价格相同则按稳定顺序处理。
- 自动购买的商品来自网络成员可交易的现实商人，不向虚空商人购买。同物品有多个来源报价时优先购买便宜来源；不同价格作为不同报价保留。交易消耗该现实商人的库存，并按当前商人报价与管理员加成结算。
- 计划时间按游戏内时间计算。时间为每天 5 点、间隔 2 天时，从下一游戏日 5 点开始，之后每隔两个游戏日检查一次。每个定时点只检查一次，不重试；条件不满足、来源繁忙或交易失败后等待下一个定时点或管理员手动执行。
- 每次自动购买只在实际执行期间锁定将交易的商人，完成、失败或取消后释放锁。占用中的来源跳过；手动界面已锁住所有商人时不等待，不重试。执行时重新验证可用库存、报价和网络余额，不能只依赖打开界面或上次扫描时的缓存。

**执行条件比较符**

数量、货币和品质的条件统一支持 `>`、`>=`、`=`、`<=`、`<`。货币条件只判断本次规则是否启动，不代表需要保留的最低余额；实际最高支出由单次最高花费和可用余额共同限制。

- 合成链在哪里启动，产物进入玩家背包、工作站还是网络？工作站类型、技能/解锁和配方选择如何限制？

- 即时制作、即时拆解、即时维修分别绕过哪些原版时间或队列规则，材料和技能收益如何计算？

## 阶段 6：性能和发布验证

- 对 1 千、3 万和 10 万精确物品变体做基准，包含单变体超出 `int32.MaxValue` 的数量；记录 P50/P95 和内存分配。
