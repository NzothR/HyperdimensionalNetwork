## 自动售出刷新手持物品动画（2026-10-20，待游戏内复验）

- 自动售出背包物品时，服务端此前会同时重写未变化的快捷栏快照；应用快照会重新选择当前快捷栏格。客户端随后还会无条件刷新快捷栏，因此手持武器可能重播切换动画。

## 不可丢弃任务物品保护（2026-10-20，待游戏内复验）

- 本轮日志已包含用户确认成功的塔科夫换弹事务，但任务物品取出尝试没有进入网络取出日志。源码确认网络投影格使用快捷栏位置，原版因此对任务物品设置 QuestLock；任务目标提交只扣背包／快捷栏物品。
- 以原版 `ItemClass.CanDrop` 为统一界限：不可丢弃物品拒绝手动和批量入库，不参与自动化规则，不可从旧网络库存取到鼠标或掉落地面；旧库存可直接取回背包。手动垃圾桶禁止这类物品进入，关闭时仍有保留及归还保护。
- 对旧版本已存入的任务物品，任务交付时按原版实际扣除的背包／快捷栏数量补扣网络剩余数量；远程客户端走服务端校验任务、物品及数量的独立请求。仅单人网络会在房主进入存档时，对没有同类进行中任务的已完成任务遗留物品做一次清理。共享网络不自动清理历史库存，服务器管理员可使用 `hdn-network-admin cleanup-quest-item <networkId> <itemName> <count> --confirm` 定向清理，避免误删其他成员任务物品。
- 已编译；待在游戏内复验旧白河补给取回、已完成任务遗留清理、新补给拒绝入库、批量入库跳过、垃圾桶和自动销毁保护，以及远程客户端交付事务。

## 自动分解与网络休眠（2026-10-20，待游戏内验收）

- 管理员可在现有自动化规则中选择“自动分解”，沿用单件/分类、品质、黑名单、数量条件及来源设置；来源为仅网络入库、仅背包和快捷栏、两者。处理顺序为分解、售出、销毁，分解不了的物品继续交给后续规则。
- 服务端用原版分解配方计算消耗、产出和耗时。管理员在线时使用管理员当前的分解时间技能与 Buff；管理员离线但仍有成员在线时使用原版基础耗时。任务进入按网络保存的隐藏队列，产物在完成时入网络。分解产物可继续经过售出及销毁规则，但本次产物不再次进入自动分解，以阻断循环。
- 网络全部成员离线时，分解队列停止计时，入库、玩家库存与商人定时规则停止执行；成员返回后恢复。商人定时规则在错过执行日后最多补执行一次。正常退出时保存队列和剩余时间；网络合并时将未完成任务迁入目标网络。
- 队列文件以准备扣料、运行、准备产出阶段及网络库存修订号恢复网络来源任务。玩家背包／快捷栏来源与队列使用分别保存的存档数据；突发进程崩溃时两份数据之间仍有极短的未提交窗口，需游戏内验证并进一步加固。当前队列不提供可视化页面。
- 已编译、XML 已解析；待验证单机与远程客户端三种来源、优先级、管理员在线与离线耗时、多人休眠与唤醒、正常退出恢复、网络合并及异常退出一致性。

## 网络库存物品分解复制漏洞修复（2026-10-20，待游戏内复验）

- 原版分解入口会把网络格中的投影堆栈直接放进制作队列，并只修改该 UI 堆栈；此前没有提交网络库存扣料，导致可无限分解。现在网络来源走独立服务端扣料事务，确认扣料后才提交原版分解队列；队列拒绝时通过绑定原扣料请求的退款事务恢复网络物品。
- 取消分解仍由原版流程把队列原料退回玩家背包，因此网络库存已扣除对应数量，不会同时保留原物品。关键请求、扣料、入队和退款阶段均有 `DebugLog` 诊断。
- 审计网络格的原版物品动作后，使用（治疗、阅读、任务、打开）、维修、改装、穿戴等单件动作先将一件网络物品正式转入玩家背包，再调用原版动作；维修目标由真实背包物品进入队列，原有维修工具/材料扣除及远程网络材料预留逻辑继续执行。若背包无空间则不启动动作。
- 丢弃动作改为服务端先扣网络物品再生成掉落物；拆解单独在入队前扣除实际拆解数量。出售已有网络事务补丁；取出/查询配方等入口不执行消耗型物品动作。
- 已编译，待游戏内验证单机/远程客户端分解、取消队列、队列已满时不扣料，维修材料分别来自背包和网络时的扣除，以及使用/改装/穿戴/丢弃的同步与堆叠行为。
