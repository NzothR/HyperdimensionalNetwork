# 功能验收状态

本文是功能验收状态的唯一索引，后续开发计划、回归范围和多人兼容工作以此状态为准。设计文档说明目标行为；本文区分原有单机功能验收与多人改造验收，避免把构建成功误记为游戏内验收。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 已验收 | 已按对应运行模式在游戏内完成验收。 |
| 实现完成，待游戏验收 | 代码已完成并构建/部署，但尚未完成对应模式的游戏内验收。 |
| 进行中 | 正在实现或修复。 |
| 未开始 | 尚未实现。 |

“原有功能”表示该阶段多人改造前已验收的单机行为；“多人兼容”表示房主/服务端与远程客户端通过服务端权威网络使用各自独立网络。

## 本轮验收约定

- 阶段 2/3 的多人兼容必须保留本表“功能范围”中的原版手势、配方/品质匹配、消耗数量及队列/世界状态行为。
- 阶段 2/3 多人兼容已由用户完成游戏内验收。补货功能按独立功能继续开发和验收。
- 补货修复包括：自动请求无可补容量时不启动冷却；自动目标范围仅含“仅快捷栏”“仅锁定格”“快捷栏+锁定格”。以上修复部署后仍需游戏内复验。
- 自动补货比较背包与快捷栏所有格子的堆叠快照；任意格子的数量变化都会触发对已设置目标范围的扫描，补货仍仅限快捷栏和/或锁定格中的已有堆叠。锁定格饮水场景仍需游戏内复验。
- 网络补货开关按 NetworkId 独立持久化，默认开启且仅管理员可见/修改；关闭时服务端拒绝手动和自动补货。网络合并应保留主网设置。
- 弹药银行按原版枪械、弓弩、发射器换弹完成后的剩余容量补网络弹药，个人实体弹药优先；备弹显示通过批量缓存查询。默认开启且只有管理员可见/修改。需游戏内验收混合弹药、整弹匣、发射器、取消/中断、弹种切换和远程客户端并发扣料。
- 不得将客户端缓存的数量作为扣料授权；实际网络扣料必须由服务端按可信玩家身份执行。
- 所有核心流程与不确定边界的诊断日志通过统一 `DebugLog` 控制。

## 本轮新增修复（待游戏内复验）

- 顶部工具栏从左到右为手动补货、设置、搜索栏、翻页；翻页靠右，搜索栏紧邻其左侧。
- 设置按钮和值按钮使用深色背景与白色文字，避免明亮背景盖住文字。入口、设置、手动补货和一键存入按钮改用用户提供的 AE2 像素图标；16×16 素材以最近邻放大到 64×64，保留像素边缘。
- “关闭超维网络后保留搜索内容”是玩家个人设置，默认开启；关闭时只清空该玩家本地 UI 的搜索词。共享网络中的其他成员互不影响。
- 存档身份使用 `World.Guid`，并在首次为玩家解析网络之前校验。GUID 不变时继续使用原网络；同一路径出现新的世界 GUID 时，清理该存档目录下本 Mod 的旧数据，再等玩家首次访问时创建新的私有网络。不得删除整个存档或其他 Mod 的数据。
- 玩家个人补货设置文件迁移到 v3；旧 v1/v2 记录的搜索保留选项默认开启。现有无身份标记的 Mod 数据会在首次启动时归属当前存档，以保留正常游玩存档。
- 本轮代码构建/部署后仍需游戏验收：同名重建存档不继承旧网络物品、已有正常存档保留、工具栏排列、图标加载、暗色设置控件、搜索开关及多人共享网络下个人设置独立。
