# 功能验收状态

本文是功能验收状态的唯一索引，后续开发计划、回归范围和多人兼容工作以此状态为准。设计文档说明目标行为；本文区分单机功能验收与多人验收，避免把构建成功误记为游戏内验收。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 已验收 | 已按对应运行模式在游戏内完成验收。 |
| 实现完成，待游戏验收 | 代码已完成并构建/部署，但尚未完成对应模式的游戏内验收。 |
| 进行中 | 正在实现或修复。 |
| 未开始 | 尚未实现。 |

“原有功能”表示该阶段多人改造前已验收的单机行为；“多人兼容”表示房主/服务端与远程客户端通过服务端权威网络使用各自独立网络。

## 多人验收约定

- 阶段 1–3、补货、弹药银行和合成链的单机功能已验收；这些功能的多人兼容尚未验收，集中安排在阶段 5。
- 多人验证须确认真实操作者、网络授权、并发扣料/加料、断线和重试语义；客户端缓存不能作为扣料授权。
- 补货多人回归范围：网络开关按 NetworkId 隔离；自动设置按玩家隔离；服务端关闭开关时拒绝手动及自动补货；并发请求不重复扣料。
- 弹药银行多人回归范围：服务端按真实玩家和当前网络原子扣料；混合弹药、整弹匣、发射器、取消/中断、弹种切换及并发消费。
- 合成链多人回归范围：服务端物品交接、取消/退款、发起者离线/退出网络/被踢时的清理，以及共享网络的可见性和权限。
- 不得将客户端缓存的数量作为扣料授权；实际网络扣料必须由服务端按可信玩家身份执行。
- 所有核心流程与不确定边界的诊断日志通过统一 `DebugLog` 控制。
