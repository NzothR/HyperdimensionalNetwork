# 超维网络

这是全新模组“超维网络”的工作目录。旧 `DestroyStorage` 仅作为功能和游戏接入点的参考，旧模组保持不变。

设计目标是提供大型随身存储网络，让游戏及已适配的模组通过统一接口查询、精确匹配、预留和消耗网络物品，不把海量虚拟物品伪装成普通背包格子。

## 当前状态

截至 2026-10-20，用户确认现有功能均已通过单项测试，包括单机及另一名玩家参与的多人测试；范围包括阶段 1–5、补货、弹药银行、合成链和商人交易。长时间连续游玩的稳定性观察仍待后续完成。完整状态见[功能验收状态](docs/acceptance_status.md)。新增物流功能继续从设计阶段考虑多人语义。

阶段 5 成员邀请/加入/退出/踢出及管理 UI、玩家成员指令和服务器管理员维护指令已实现，并通过单项多人测试。可选网络插件暂缓；基础物流可独立使用。模组定位为物流，UI 随功能逐项设计；即时制作/拆解/维修、材料返还、种植加速和存储过滤等功能不在范围内。跨版本适配层与公开 API 为低优先级可选工作。

## 已实现的功能

- 导航栏左侧书本图标直接打开网络，无需解锁物品或 Buff。
- 从背包和战利品容器一键存入；逐格拖放存入/取出；支持分页、搜索和分类。
- 可配置快捷键：`OpenNetworkKey`（默认 `O`）切换超维网络窗口，`DepositContainerKey`（默认 `D`）将当前打开的战利品/实体背包窗口（箱柜、掉落袋、载具、无人机等）的物品一键存入网络；按键只处理当前窗口，不搜索周边容器。对遵循原版 `ContainerStandardControls`、`XUiC_LootContainer` 或实体 `Bag` 数据路径的窗口使用统一适配；采用完全自定义物品存储的模组需要提供相应服务端适配。设置 `None` 可关闭对应快捷键。多人游戏时，主机和所有客户端需要使用同一版本模组。
- 左键网络取出一组；右键取出半堆，先按物品堆叠上限封顶。背包 Shift+右键存入半堆，网络 Shift+右键取出半堆。
- 网络数量以 `long` 保存；界面和游戏 `ItemStack` 投影不超过 `int32.MaxValue`。
- 玩家库存查询、配方可用性/最大制作数、实际扣料及工作站输入材料访问网络；熔炉熔炼重量仍由原版管理。
- 装备/工具维修沿用原版队列和维修计算；建筑块修复/升级与载具燃料/维修可使用网络材料。
- 手动补货按钮会填充快捷栏和背包锁定格中的已有堆叠；设置面板提供自动补货开关，以及“仅快捷栏”“仅锁定格”“快捷栏+锁定格”三个目标范围。无补货结果的自动事件不会启动冷却。设置项包含权限声明并由服务端验证。主要单机及多人流程已纳入当前验收基线。
- 游戏配置中的 `DebugLog` 默认值为 `false`；本机开发部署配置设为 `true`。
- 商人交易：网络工具栏的公爵币按钮直接切换每名玩家独立保存的手动出售开关。开启且超维网络窗口打开时，网络、背包及快捷栏物品详情显示原版交易式出售操作；只打开普通背包时不显示。出售收益可按玩家保存为背包优先（背包放不下则存网络）或直接存网络。聚合商人窗口使用原版商人风格的顶部类别、搜索、左侧商品列表、右侧物品详情与背包，关闭后返回超维网络；交易期间跨网络占用对应商人并扣减真实库存。聚合购买先用个人公爵币再用网络余额；原版商人购买也可使用网络中的公爵币。
- 商人规则入口提供网络管理员规则增删、启停、排序和“立即执行全部”；自动出售在新公共入库或新增出售规则后的现有库存扫描时运行，自动购买支持物品/品质匹配、网络物品数与公爵币比较条件、单次数量/花费上限以及按游戏日程执行。规则保存在当前存档的 Mod 数据中。
- 服务端指令 `hdn-trader-market list` 查看聚合交易锁会话；`hdn-trader-market close <sessionId>` 强制释放指定会话。
- 玩家在 F1 控制台使用 `hdn-network`（别名 `sn`）：`info`、`members`、`invite <PlayerId|在线名称>`、`invite-status`、`accept <InviteId>`、`decline <InviteId>`、`leave`、`kick <PlayerId|在线名称>` 和 `help`。邀请仍默认使用游戏原版确认弹窗；命令参数不带 `/`。
- 服务器管理员在服务器控制台使用 `hdn-network-admin`：`move-items <源网络ID> <目标网络ID>`、`clear <网络ID> --confirm`、`player-info <PlayerId>`、`list-players [偏移量] [数量]`、`set-admin <PlayerId>`、`trader-sessions`、`trader-force-close <sessionId>`。`clear` 是破坏性操作并要求显式确认；`set-admin` 按目标玩家当前所属网络切换唯一管理员。
- 商人交易主要单机及多人流程已纳入当前验收基线；具体回归范围与历史修复记录见验收文档。
